Bilkul. Neeche **WorkTrack** ka complete end-to-end **Backend + Android Mobile App API Blueprint** hai. Isko aap developer ko directly de sakte ho. Main API contracts, database entities, authentication, attendance flow, GPS/photo verification, real-time tracking aur admin dashboard integration sab cover kar raha hoon.

# 23. Attendance Architecture

Attendance should be treated as a **session**.

```text
NOT_STARTED
     ↓
CHECKING_IN
     ↓
WORKING
     ↓
CHECKING_OUT
     ↓
COMPLETED
```

Other states:

```text
REJECTED
CANCELLED
MANUAL_ADJUSTMENT
```

# 24. Check-In Flow

This is extremely important.

```text
Employee selects project
        ↓
App requests camera
        ↓
Employee takes live photo
        ↓
App gets GPS
        ↓
App checks GPS accuracy
        ↓
Send attendance request
        ↓
Backend validates project
        ↓
Backend validates employee
        ↓
Backend validates geofence
        ↓
Backend creates attendance
        ↓
Upload photo
        ↓
Attendance becomes WORKING
        ↓
WebSocket event
        ↓
Admin dashboard updates
```

# 26. Backend Check-In Validation

Backend must NOT blindly trust mobile.

It should validate:

```text
1. JWT valid?
2. Employee active?
3. Project active?
4. Employee assigned to project?
5. Employee already checked in?
6. Location coordinates valid?
7. GPS accuracy acceptable?
8. Employee inside geofence?
9. Server time?
10. Photo uploaded?
11. Duplicate request?
12. Device/session valid?
```

---

# 27. Geofence Calculation

Backend calculates distance:

```text
Employee GPS
       ↓
Project GPS
       ↓
Haversine Distance
       ↓
Distance <= Radius?
```

Example:

```text
Project Radius:
200 meters

Employee Distance:
83 meters

Result:
✓ ALLOWED
```

If:

```text
Distance:
1.4 KM

Radius:
200m

Result:
❌ OUTSIDE_GEOFENCE
```

```json
    "distance": 1420,

  }

```

```json
{
  "success": false,
  "error": {
    "code": "GPS_ACCURACY_TOO_LOW",
    "message": "Location accuracy is too low. Please move to an open area and try again."
  }

```

Already checked in:

```json
{
  "success": false,
  "error": {
    "code": "ALREADY_CHECKED_IN",
    "message": "You are already checked in."
  }
}
```

Don't send huge original camera images directly into PostgreSQL.

Use:

```text

 ↓
Compress
 ↓
Upload
 ↓

```


```text

```

# 36. Location Tracking

This needs to be designed carefully.

Do **not** continuously track employees 24/7.

Recommended:

```text
CHECKED OUT
     ↓
No tracking

CHECKED IN
     ↓
Location tracking allowed
     ↓
WORKING
     ↓
Check-out
     ↓
Tracking stops
```

This is both technically and privacy-wise better.

# 38. Location Frequency

Don't send GPS every second.

Recommended:

```text
Every 1–5 minutes
```

or when:

```text
Employee moves > 50 meters
```

Adaptive tracking is better.

For example:

```text
Stationary:
5 minutes

Moving:
1 minute
```

# 49. Manual Attendance Adjustment

Admin may need to correct attendance.

Endpoint:

```text
POST /api/v1/attendance/:id/adjust
```

Request:

```json
{
  "checkInAt": "2026-10-06T09:00:00+04:00",
  "checkOutAt": "2026-10-06T17:00:00+04:00",
  "reason": "Employee forgot to check out."
}
```

Backend must record:

```text
Who changed it?
When?
Old value?
New value?
Reason?
```

Never silently overwrite attendance.

```text
Internet?
   ↙       ↘
 YES       NO
 ↓          ↓
Upload    Save locally
            ↓
       Retry automatically
```

However, **server time and server validation remain authoritative**.

For attendance, don't allow unlimited offline manipulation.

A safe approach:

- Check-in can be queued briefly.
- Capture GPS/photo metadata locally.
- Upload once connectivity returns.
- Backend records original capture timestamp separately from server receipt time.
- Flag delayed submissions for admin review.

```text
Already processed
```

**Mobile app ko attendance ka final authority mat banana.**

```text

```

**Final decision backend kare:**

```text

Is GPS accurate?
```

Phir backend final record create kare. Is architecture se employee app ko manipulate karke fake attendance create karna kaafi mushkil ho jayega.
